# Публикация 06 — без обложки

**Дата публикации:** 2026-10-18 (18.10.2026)

## Русская версия

**Заголовок:** Почему систему нужно проектировать с учётом исключений

**Короткий анонс:** Нормальный сценарий показывает, как должно работать приложение. Исключения показывают, будет ли оно полезным в реальной работе.

**Текст статьи:**

Большинство процессов легко описать, пока всё идёт по плану: заявка заполнена правильно, данные на месте, нужный сотрудник доступен. Но в реальной работе встречаются дубликаты, неполные сведения, отмены и ситуации, когда следующий шаг временно невозможен.

Перед разработкой полезно собрать не только основной сценарий, но и список частых исключений. Что может пойти не так? Кто вправе исправить ситуацию? Нужно ли сохранить незавершённую работу? Как пользователь поймёт, что именно требуется от него?

Не каждую редкую ситуацию нужно автоматизировать. Иногда достаточно понятного сообщения и способа продолжить вручную. Главное — решить это заранее, чтобы ошибка не превращалась в тупик и не приводила к потере данных.

## English version

**Publication date:** 2026-10-18

**Title:** Why software should account for exceptions

**Short summary:** The standard workflow describes how an application should work. Exceptions reveal whether it will be useful in day-to-day operations.

**Article:**

Most processes are easy to describe when everything goes according to plan: a request is complete, the data is available, and the right person is ready. Real work also includes duplicates, missing details, cancellations, and cases where the next step is temporarily impossible.

Before development, document the main workflow and the common exceptions. What can go wrong? Who can resolve it? Should unfinished work be saved? How will the user know what to do next?

Not every rare case needs automation. Sometimes a clear message and a safe manual path are enough. The important part is to decide in advance so an error does not become a dead end or cause data loss.
